## 三、环境坑（下午直接用，别再踩）

1. **pip / uv 全部不可用**
   - `pip install --target` → `PermissionError: ...pip-unpack-xxx\*.whl.metadata`
   - `uv pip install` → 缓存目录拒绝访问 / 无法启动任何 python.exe 子进程
   - **唯一可行**：PyPI JSON API 手动下 wheel → `zipfile.extractall(libs)`。已有脚本模式可复用。
2. **sherpa-onnx-core 必须显式选 `py3-none-win_amd64`**，自动匹配会装成 android 版（导入能过，一跑就崩）。
3. **ollama 调 qwen3.5 必须传 `num_ctx≈2048` + `think=false`**，否则 20GB 内存 + 只出思考不出译文。
4. **目录被锁**：`models\sherpa-onnx-zipformer-ja-reazonspeech-2024-08-01`（tarfile 直接解压出来的那个）**无权限读/改名/删**。已跑过 ACL 修复脚本，判定 `NOT_THIS_CLASS`，未修复。绕开办法：逐成员手动写入新目录（`extract_model.py` 已验证可行）。等 `model_ja/` 跑通后，可以把 `models/ja-reazon.tar.bz2`（713MB）删掉腾空间。
5. **控制台乱码**：跑任何带日文的脚本前加 `PYTHONIOENCODING=utf-8`，脚本里也 `sys.stdout.reconfigure(encoding='utf-8')`。
6. **ffmpeg 不在 PATH**：读音频走 `sherpa_onnx.read_wave`，别依赖 ffmpeg。

## 六、关键结论（已调研确认，别推翻）

- **主线必须是"VAD 整句翻译"**，不要做逐字流式翻译。日语动词/否定在句尾，前缀翻译 13 倍于反方向会被推翻，否定极性约 0.7 会翻错。
- ReazonSpeech 在自家基准上优于 Whisper-large-v3（TEDx 9.09 vs 9.96），int8 只 154MB，且**结构上没有 Whisper 那种"静音补一句话"的幻觉**，代价是不带标点。
- 云端一劳永逸方案是阿里 **Qwen3.8-LiveTranslate**（字均延迟 2.3s，60 语种，`output_modalities=["text"]` 正好只要字幕），但权重不开放、按量计费；本地这套显存占用 <4GB，零成本。
